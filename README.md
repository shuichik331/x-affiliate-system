# Xアフィリエイト運用システム — 初期版

X（旧Twitter）でのアフィリエイト運用を、情報収集から振り返りまで一つのローカル画面で管理するMVPです。最初から架空サンプルが入り、APIキーなしで試せます。

## できること

1. キーワード・ジャンル・参考アカウント・収集期間を設定した、X投稿データの手入力と架空サンプル収集（将来X APIに差し替え可能なProvider構造）
2. 反応率・フォロワー数に対する伸びを示す「バズスコア」・フック/構成/CTA/訴求パターンのルールベース分析（将来LLM分析に差し替え可能な構造）
3. アカウント方針とプロフィールの設計
4. 案件候補、申請状況、提携後URLの管理（ジャンル・ターゲット・訴求ポイント・報酬条件・禁止表現・案件メモ）。提携承認済みの案件は、バズ投稿分析・プロフィールと比較した0〜100点の「マッチ度」とその理由を確認できる（将来AI判定に差し替え可能な構造）
5. マッチ度の高い組み合わせから「投稿企画」（ターゲット・テーマ・フック・構成・訴求・CTA）を作成し、そこから5つの明確なスタイル（結論先出し型・問題提起型・比較型・箇条書き型・短文型）で投稿テンプレートを新規生成（将来LLM Providerに差し替え可能な構造）。発信方針と案件から直接テンプレートを作ることも可能。バズ投稿の構成・フックだけを参考にし、原文はコピーしない
6. PR表示、案件状態、リンク、禁止表現、概算文字数、危険表現の検品と人による承認
7. 承認済みの下書きに「Xで投稿」ボタン。押すとX公式の投稿作成画面（Web Intent）が本文入力済みで新しいタブに開き、内容を確認して「ポストする」を押すだけの状態にする（自動投稿ではなく、最後の操作は必ず自分で行う）。投稿後はそのURLを登録して「投稿済み」として記録（投稿URL・日時・使用した案件/企画/参考分析）。公開中・停止・削除の状態管理。**Web Intent方式では実際に投稿されたかどうかをアプリ側では自動判定できないため、URL登録は必ず自分で行う**（将来、公式X APIに差し替え可能なProvider構造）
8. 投稿ごとに表示回数・いいね・リポスト・返信・リンククリック・成果・売上を手入力し、CTR・CVR・エンゲージメント率・EPC（1クリックあたり報酬）・1000impあたり報酬を自動計算。投稿別・案件別に比較し、どのフック・構成・訴求・CTAが成果につながったかを確認できる

ダッシュボードには「今日やること」（分析待ちの参考投稿、承認済み案件、下書き未作成の企画、投稿待ちの下書き、成果未入力の投稿）を表示し、次に何をすべきかが一目で分かります。「①情報収集→②バズ分析→③プロフィール設計→④案件管理→⑤投稿企画・制作→⑥検品→⑦投稿管理→⑧成果分析」の運用フローも確認できます。

外部サービスへの実接続、ASPへの申請、Xへの自動投稿は行いません。投稿は必ず自分の手でXに行い、その後アプリに記録します。**最初の報酬が発生するまでは、Claude/OpenAI等のLLM API・X API・ASPのAPIを一切使わない方針**です（`docs/ARCHITECTURE.md` を参照）。

## 起動方法

Python 3.8以上だけで動きます。追加インストールは不要です。

```bash
cd /path/to/x-affiliate-system
python3 -m app.server
```

ブラウザで <http://127.0.0.1:8765> を開きます。停止はターミナルで `Ctrl+C` です。入力データは `data/workspace.sqlite3` に保存されます。

別のポートを使う場合:

```bash
python3 -m app.server --port 9000
```

## テスト

```bash
python3 -m unittest discover -s tests -v
```

## 安全設計

- `.env`、APIキー、ローカルDBをGitの対象外に設定
- サーバーはMac内の `127.0.0.1` だけで待受
- 外部通信を行わず、`APP_MODE=mock` 以外は起動時に停止
- 有料API（Claude/OpenAI等のLLM、X API、ASPのAPI）は未接続。APIキーの取得・設定は不要
- Xへの自動投稿・ASPへの自動申請はどの画面からも行わない。「Xで投稿」はX公式Web Intentの投稿作成画面を開くだけで、Xのログイン情報・Cookie・セッション・アクセストークンは一切取得・保存しない
- 「Xで投稿」ボタンを押しただけ、または投稿画面を開いただけでは`published`にならない。有効なXの投稿URL（x.com/ユーザー名/status/数字の形式）を自分で登録して初めて`published`になる
- 下書きを変更すると検品と承認を無効化
- 承認・書き出し直前に検品を再実行
- 投稿済みの記録は、検品に合格した承認済み下書きに限定
- 架空サンプルの書き出しには「公開不可」を自動追記
- 成果の入力は、実際に投稿済みとして記録した投稿に限定

詳しい考え方は [設計](docs/ARCHITECTURE.md) と [運用ガイド](docs/OPERATIONS.md) を参照してください。
